# Easy WAL 架构设计（精简版）

## 设计理念

**核心原则**：
- **单一入口**：WAL 对象既是唯一对外接口，也是内部段管理协调者
- **状态一致**：读写共享同一个段对象，状态集中在 WAL 对象
- **职责清晰**：LogSegment 只负责段内操作，WAL 对象负责段管理决策
- **极简架构**：2 层设计（WAL → LogSegment），无独立协调层

## 核心组件

### WAL 对象
- 管理段集合（创建、轮转、删除）
- 提供读写接口
- 维护全局状态（活跃段 ID、位置）
- 内置优化策略（预读缓冲区、批量写入）

### LogSegment 对象
- 单个段的读写操作
- 数据格式：[Magic][Length][CRC][Data]
- 维护文件句柄和读写位置

## 关键决策

### 并发模型
- **选择 RwLock**：读操作可并发，写操作互斥
- WAL 对象状态用 RwLock 保护
- LogSegment 文件操作用内部锁

### 持久化策略
- **支持多种模式**：
  - 立即持久化：每次写入都 fsync（高可靠性）
  - 批量持久化：积累一定量再 fsync（高性能）
  - 手动持久化：用户决定何时 fsync（灵活控制）

### 错误处理
- **写入失败**：返回错误，不自动重试
- **读取损坏**：返回错误，提供完整性检查工具
- **段切换失败**：返回错误，用户决定如何处理

## 参考设计思路

### Kafka Log（主要参考）
- Log 对象直接管理 LogSegments 集合
- LogSegment 读写合一，无独立 Writer/Reader
- 状态集中在 Log 对象

### etcd/raft WAL
- WAL 结构直接提供读写接口
- 无独立 Reader/Writer 对象
- 极简设计，职责清晰

### RocksDB WAL
- Writer/Reader 直接操作文件
- 无中间管理层
- 简单直接的读写接口

## 实施优先级

1. 实现 WAL 对象和 LogSegment（最小可用版本）
2. 实现基本读写功能
3. 实现段轮转策略
4. 添加预读缓冲区和批量写入优化
5. 实现崩溃恢复和完整性检查
