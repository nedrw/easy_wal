# Easy WAL 架构设计

## 设计理念

**极简设计**：借鉴 Kafka Log 的设计思想，避免过度分层，状态集中管理。

**核心原则**：
- 单一入口：WAL 对象作为唯一对外接口
- 状态一致：读写共享同一个段对象
- 职责清晰：组件层只负责段内操作，协调层负责段管理决策

## 核心组件

### 1. WAL 对象（对外接口）

**职责**：
- 管理段集合（段创建、轮转、删除）
- 提供读写接口
- 维护全局状态（活跃段 ID、写入位置）
- 内置优化策略（预读缓冲区、批量写入）

**设计思路**：
- 直接管理 LogSegment 对象，无需中间协调层
- 段轮转策略内置（大小、时间、记录数）
- 预读缓冲区作为内部辅助对象

### 2. LogSegment 对象（段读写）

**职责**：
- 单个段的读写操作
- 共享文件句柄和写入位置
- 数据格式管理（Magic + Length + CRC + Data）

**设计思路**：
- 读写功能合一，共享状态
- 只负责段内操作，不决策段切换
- 简单直接的读写接口

## 参考对象设计思路

### Kafka Log（主要参考）

**架构特点**：
- Log 对象直接管理 LogSegments 集合
- LogSegment 包含读写功能，无独立的 Writer/Reader
- 段轮转策略内置在 Log 对象中
- 预读缓冲区在读取方法内部处理

**关键设计**：
- 层数极简：Log → LogSegment → FileRecords
- 状态集中：所有段状态在 Log 对象中
- 读写合一：LogSegment 同时提供 append() 和 read()

### etcd/raft WAL

**架构特点**：
- WAL 结构直接提供读写接口
- 读取是独立函数，不是对象方法
- 极简设计，职责清晰

**关键设计**：
- 无独立的 Reader/Writer 对象
- 状态管理集中在 WAL 结构
- 读取通过 ReadAll() 函数实现

### RocksDB WAL

**架构特点**：
- log::Writer 和 log::Reader 直接操作文件
- 无独立的协调层
- 简单直接的读写接口

**关键设计**：
- Writer 提供 AddRecord() 方法
- Reader 提供 ReadRecord() 方法
- 无中间管理层

### SQLite WAL

**架构特点**：
- Wal 对象直接提供读写功能
- 无独立的协调器
- 段管理内置在 Wal 对象中

**关键设计**：
- WalRead() 和 WalWrite() 直接操作
- 段轮转策略内置
- 极简架构

## 架构对比

| 设计 | 层数 | 协调层 | 状态管理 | 复杂度 |
|------|------|--------|----------|--------|
| Easy WAL (新) | 2层 | 无 | WAL对象集中 | 低 |
| Kafka Log | 2层 | 无 | Log对象集中 | 低 |
| etcd WAL | 1-2层 | 无 | WAL结构集中 | 极低 |
| RocksDB WAL | 2层 | 无 | 分散在Writer/Reader | 低 |
| SQLite WAL | 2层 | 无 | Wal对象集中 | 极低 |

## 实施策略

**优先级**：
1. 实现核心 WAL 对象和 LogSegment
2. 实现基本的读写功能
3. 添加段轮转策略
4. 优化：预读缓冲区、批量写入
5. 恢复功能：崩溃恢复、完整性检查

**验证方式**：
- 单元测试覆盖核心功能
- 集成测试验证读写一致性
- 性能测试对比主流 WAL 库
